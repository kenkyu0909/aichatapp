## 今回のオフライン修正

- 買い物の一般的な好みと、即決・比較・検討などの具体的行動を分け、回答と矛盾する候補を拒否する。
- カレーの好み・食べる頻度・最近食べた経験を分けて確認する。
- カフェが趣味というだけでは、静かさや雰囲気の好みを確認済みにしない。
- `consider_invite`の根拠が相互の関心や自然な機会を明示する場合、誘い候補との一致を1回だけ修復する。不一致が残ればエラーにする。
- API優先順位の検証をAPI別名とモデル名の4組の厳密な順序で行う。

### 追加レビュー後の境界確認

後続レビューで見つかった境界ケースをさらに修正し、オフラインで再確認しました。

- 買い方の否定では「衝動買いを避ける」「控える」に加え、「すぐ買うのは避ける」「即決購入を控える」も、反対の行動を支える根拠として扱わない。
- カレーの頻度や最近の経験を、別項目に書かれた読書・映画の「よく」「最近」で裏付けない。専用プロフィール項目、カレーへの確認回答、またはカレーと同じ文脈にある根拠を必要とする。
- カフェの好みでは比較表現の極性を保持し、「落ち着いた雰囲気よりにぎやかな店が好き」を「落ち着いた店が好き」に反転させない。
- 誘い機会では、直近2件の相手発言のつながる話題を使い、カフェへの関心と無関係な質問の寄せ集めを避ける。「カフェは好きですか？」のような本人への質問だけを相手自身の関心表明に数えない。明確な外出先への消極表現を除外し、過去の誘い・拒否は会話全体で保持する。返信遅延への謝罪だけを拒否と誤判定しない。
