## この結果を受けて実施した修正

実出力で、根拠のない本人事実が候補に混ざった後、その内容を本人へ尋ねてしまう経路を確認した。本人への確認は、相手が直接尋ねた未確認事実に限るよう変更した。無関係な主張が1回の修正後も残る場合は、追加質問へ変換せず候補生成を終了する。

また、相手が本人へ質問していないのにモデルが不要な本人質問を返した場合、追加で1回だけ「安全な返信を作る」再生成を行う。再度不適切なら停止する。無制限の再試行はしない。

追加したオフラインテストは、無関係な本人質問を返さないこと、不要なモデル質問から安全な候補へ1回で回復すること、`invite_gently`と誘い候補が一致することを確認する。これらはモックの検証であり、今回の実API失敗を成功へ置き換えるものではない。

## 結論と限界

今回の品質判定は**FAIL**。実APIの疎通は確認できたが、本人情報の回答反映、冗談への適応、候補の多様性、誘いの判断、断り後の話題選びに未解決の問題が残る。安全ゲートは一部の危険な候補を非表示にしたものの、自然で有用な候補を安定して返す状態ではない。
